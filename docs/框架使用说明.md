# 问答线实验使用说明

比较 T1–T6 对同一批 API 问答题的回答。题面只有 `Question` 和系统提示。标准答案、别名和出处只留在评分程序里。环境用 `uv`，不要提交 `.venv` 或 `.venvs`。本线不启动 OSIS 求解器。

```powershell
$env:OSIS_PARENT_REPO = "C:\path\to\osis-skill-enhance-main"
$env:OSIS_MODEL_API_KEY = "<key>"
$env:OSIS_MODEL_BASE_URL = "http://<gateway>/v1"
$env:WEKNORA_API_KEY = "<weknora-key>"
uv sync --python 3.13 --extra test
uv run python scripts/setup_framework_envs.py
uv run python scripts/create_knowledge_snapshot.py `
  --parent-repo $env:OSIS_PARENT_REPO `
  --output tmp\qa-knowledge-snapshot
```

快照是父仓库 `.agents/skills` 的完整副本，含模板画像和参考文件。`datasets/qa/questions.json` 不会复制进去。

## 怎么开跑

不调模型，只核对题号：

```powershell
uv run python scripts/run_dataset.py `
  --parent-repo $env:OSIS_PARENT_REPO `
  --architecture T2 `
  --skills-dir tmp\qa-knowledge-snapshot `
  --dry-run
```

一条正式任务。`--architecture` 换成 T1–T5。T6 另见下文，须先有父仓库 OpenCode：

```powershell
uv run python scripts/run_dataset.py `
  --parent-repo $env:OSIS_PARENT_REPO `
  --architecture T2 `
  --skills-dir tmp\qa-knowledge-snapshot `
  --model $env:OSIS_MODEL `
  --label formal-qa `
  --seed 0
```

六架构一起跑：

```powershell
uv run python scripts/run_campaign.py `
  --parent-repo $env:OSIS_PARENT_REPO `
  --architectures T1 T2 T3 T4 T5 T6 `
  --skills-dir tmp\qa-knowledge-snapshot `
  --model $env:OSIS_MODEL `
  --base-url $env:OSIS_MODEL_BASE_URL `
  --label formal-qa `
  --seed 0 `
  --jobs 1 `
  --resume
```

评分抽取最后一个 `FINAL ANSWER:`，按父仓库规则做准精确匹配。综合分是准确率 80% 加耗时效率 20%。失败、超时或没有最终答案的题记 0 分，仍计入分母。

## 并行还是串行

`--jobs` 只作用于 T1–T5，默认 1。这些架构不占 OSIS 端口，可以并行，但共用一个模型网关。正式对比建议 `--jobs 1`，避免网关 429 或 503 把耗时差进分数。

T6 复用父仓库已经打开的 OpenCode（默认 `http://127.0.0.1:4096`），campaign 始终串行。跑 T6 前先按父仓库方式执行 `opencode serve`，不要在实验仓库另起一套服务。

`--resume` 跳过已完成的当前 attempt。同一 label 再次开跑时，旧目录会先归档。结果在 `runs/` 和 `results/`，不进 Git。汇总方法见 [实验数据后处理.md](实验数据后处理.md)。

## T1–T5

T1、T2 用仓库 `.venv`。T3–T5 用 `.venvs/t3`、`t4`、`t5`。驱动会自己选解释器。

| 架构 | 动作 | 本地技能怎么给 | 写出什么 |
| --- | --- | --- | --- |
| T1 | 一次 `/chat/completions`，没有工具循环 | 快照按路径排序，整份放进提示词 | 一行 `FINAL ANSWER:` |
| T2 | LangGraph `create_agent`，JSON 工具 | 本地技能只读工具，外加 `list_knowledge_bases`、`hybrid_search` | 最终答案文本。没有写文件工具 |
| T3 | smolagents `CodeAgent` | `pathlib` 读本地快照，并调用同两个只读知识库工具 | `final_answer` 里的 `FINAL ANSWER:` |
| T4 | OpenHands 默认智能体 | `invoke_skill` 加官方终端、文件编辑器，再加同两个知识库工具 | 浏览器关闭 |
| T5 | CrewAI 三角色：检索、作答、复核 | `Crew(skills=...)`，三个角色都能调用同两个知识库工具 | 复核者不能改文件。允许委派 |

T1 因为没有工具，才把整份快照放进提示词。T2 的工具是 LangGraph 没有领域工具时必须由调用方传入的，内容仍是这份快照，不是另一套文档。

T2–T5 与 T6 一样只做检索：`list_knowledge_bases`，再 `hybrid_search`。不建会话，也不调用 `agent-chat`。未设置 `WEKNORA_API_KEY` 时，从父仓库 `.agents/opencode.json` 的 `mcp.weknora.environment` 读取检索密钥和地址。环境变量若已设置，则以环境变量为准。思考强度默认 `low`，也可用 `--variant low`。T1 没有工具循环，不能现场查库。

## T6

T6 调用父仓库 `datasets/qa/run_eval.py` 的 `chat_via_agent`。技能、WeKnora 和权限都在父仓库已经运行的 OpenCode 上。实验仓库不改 bash、编辑或外部目录权限，也不复制带密钥的 `opencode.json`。题面仍只有系统提示和 `Question`。
