# 框架使用说明

## 公平输入

T6 使用父仓库问答代理及其 OpenCode 里的技能。T1–T5 拿到同一份 `.agents/skills` 的完整副本。题面都是同一个 `Question` 和 system prompt。差别只在框架。task_id 与 category 只由 runner 用于运行标识和分组统计。gold、aliases、source 和父仓库 scorer 也只在统一 runner 内可见。

## T1 Direct

一次 `/chat/completions` 请求。无工具、无自我修正循环。为保持知识可达性，快照按路径排序后完整注入 prompt。

## T2 LangGraph

使用 `create_agent` 与流式 ReAct。LangGraph 没有领域工具，调用方传入与建模线相同的只读面：技能列表、技能正文、参考文件、模板文件列表、案例搜索，以及知识文件的列举、检索和读取。问答没有候选工程，因此没有写文件工具。

## T3 smolagents

使用 `CodeAgent`，`tools=[]`。解释器放行 `json` 和 `pathlib`，模型自己读知识目录。不注册自建检索工具。

## T4 OpenHands

使用 `load_skills_from_dir` 和 `get_default_tools(enable_browser=False)`：终端、文件编辑器、任务跟踪。技能正文由原生 `invoke_skill` 加载。工作目录是知识快照，不注册自建读写工具。

## T5 CrewAI

顺序执行 researcher、answerer、reviewer。`Crew(skills=...)` 挂载技能，`allow_delegation=True`。文件工具是 CrewAI 的 DirectoryReadTool、FileReadTool、FileWriterTool。复核者只读。`load_skill` 只返回 SKILL.md，因此保留 `read_skill_resource`。代码解释器保持关闭，与建模线一致。

## T6 OSIS-AI

T6 不在本仓库启动 OpenCode，也不改 bash、edit 或外部目录权限。它调用父仓库 `datasets/qa/run_eval.py` 的 `chat_via_agent`，连父仓库已经在跑的 OpenCode。题面只含系统提示和 Question。T6 始终串行。
